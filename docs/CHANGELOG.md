## [Unreleased]

### 新增
- **图形化虚拟设备** `tools/virtual_device/`：独立可运行的 Modbus TCP 从站（C++/Qt，
  **不链接主程序任何代码**）。界面实时显示寄存器工程值；支持故障注入（冻结数据 / 强制越限 /
  掐断所有连接）与**写入保持**（下位机被写入后不再被自动波动覆盖）；点位表与主程序
  `defaultTagPoints()` 严格对齐，监控端用默认点位表即可连上，无需改缩放
- **协议探针** `tools/virtual_device/protocol_probe.py`：零依赖脚本，用**真实报文**断言
  0x01 / 0x03 / 0x04 / 0x05 / 0x06 与异常响应、MBAP 事务号回填 —— **19 项断言全通过**，可随时复现

### 变更
- **存储读写分离（SQLite 写线程化）**：`DataStorage` 的 SQLite 连接拆成**读 / 写两条**并各归一条线程 ——
  查询留在调用者线程，所有写操作（采样批量提交 / 告警 / 操作留痕 / 设备台账 / 保留策略清理）
  转到独立写线程执行；开启 `WAL` + `busy_timeout` 让两条连接真正并发。
  公开接口签名与语义**不变**（写操作经 `BlockingQueuedConnection` 同步转发，调用者返回时数据已落库），
  因此 **5 个单测套件零改动全通过**；`insertSample()` 保持"只入队 + 异步通知"，
  采集线程不会被写线程的 fsync 拖住

### 计划中
- 无（本轮两项均已完成）

## [v1.0.0] — 2026-09-21

> 产品化包装完成，具备"可交付现场试用"的完整度。

### 新增
- **CPack 安装包**：生成 ZIP（内含 Qt 运行时），解压到任意目录即可运行，无需配置 PATH
- **数据保留策略**：采样表只保留最近 N 天（默认 30 天）原始数据；更早数据按小时桶聚合进
  `samples_downsampled` 趋势表（avg / min / max / 计数）后删除原行，数据库不再无限增长。
  过期判定**对齐桶边界**，避免半桶丢失或重复计数
- **日志滚动**：按大小切分（默认单文件 2 MB × 保留 5 份），长期运行不会写满磁盘
- **崩溃转储**：Windows 走 `SetUnhandledExceptionFilter` + `MiniDumpWriteDump` 产 `.dmp`；
  其他平台走信号处理器产带栈的 `.txt`，现场无人值守也能留证
- **界面预览**：`docs/screenshots/` 收录真实运行截图（10 个页签）

### 修复
- `MainWindow::rebuildDeviceTree()` 中 `QSignalBlocker` 作用域过长，**把末尾"还原选中"的
  `setCurrentItem` 也一起屏蔽了** → 重建后趋势曲线与设备详情面板收不到选中同步。
  修法：把 blocker 收进只包住"清空 + 重建"的内层块

### 变更
- 主窗口标题去掉版本号后缀

## [v0.8.0] — 2026-09-17

> 技术深度：架构能力与工程规范。

### 新增
- **协议插件化**：`IProtocolPlugin`（id / 显示名 / 默认端口 / `ProtocolTraits` / 连接工厂）
  + `ProtocolRegistry`（注册 + `QPluginLoader` 动态加载）；`AcquisitionScheduler::createConnection()`
  里**再无协议 switch**，内置协议与外部插件平权；新增协议 = 丢一个动态库进 `plugins/protocols/`，
  **核心代码零重编译**。设备对话框的协议列表与字段可见性也由 traits 驱动
- **外部协议插件样板** `plugins/http_json/`（HTTP / JSON 数据源，示范"新增协议要写多少东西"）
- **单元测试 + CI**：`QTest` 五个套件（告警引擎状态机 / 工单闭环与 MTTR / 存储往返与溢出补传 /
  配置往返 / Modbus 块读与 CRC16），源码拆出 `monitor_core` 静态库使测试链接的就是产品那份代码；
  GitHub Actions 每次 push / PR 自动构建 + **零警告门槛** + `ctest`
- **性能基线夹具** `tools/bench/`（默认不编，`-DMONITOR_BUILD_BENCH=ON` 打开）：
  端到端吞吐 + 写库微基准，同时数采集次数与落库行数**对账**（防"悄悄少写几条"）

### 变更
- `DeviceInfo::protocol` 由整型枚举改为字符串 `protocolId`；`devices` 表新增 `protocol_id`
  列 + `ensureColumn` 自动迁移（老库无损升级）

### 实测
- 100 台 × 10 点位 → **1000 点/秒、单核 9.5 %**；500 台 → **4999 点/秒、单核 53.6 %**，零丢失
- 写库：攒批 **22000 条/秒** vs 逐条 **203 条/秒**（约 110 倍）

## [v0.7.0] — 2026-09-21

> 补齐工业现场最核心的业务闭环。

### 新增
- **告警工单闭环**：告警"确认"不再是点一下就完 —— 处理必须录入结论（处理人 / 动作 / 备注）并落库留痕；
  据此统计 **MTTR（平均修复时长）**，总览 KPI 墙与报表页均接入。「确认」与「处理」是两个语义
  （看见了 ≠ 处理完了），已恢复的记录拒绝再处理
- **Modbus 连续寄存器块读**：功能码 03/04 支持一次读多个连续寄存器（点位按地址排序后合并成尽量少的块），
  20 个点位从 20 次网络往返压到 **1 次**；TCP 与 RTU **共用同一份** `modbus::runPoll`，保证行为一致
- **Modbus RTU（串口）**：`QSerialPort` + CRC16 帧，整段由 `HAVE_QT_SERIALPORT` 宏护卫
  （未装 Qt6SerialPort 时自动不编译，构建照常）；`DeviceInfo` 增串口参数
  （baudRate / dataBits / parity / stopBits，刻意用 int 不碰 QSerialPort 类型，
  使配置 / 存储 / 对话框等通用层在 Windows 也能编译）
- **采样溢出队列**：落库链路不可用时采样**不丢弃**，改为追加写盘（JSON Lines，
  `<数据库名>.pending.jsonl`，64 MB 闸门）；下次启动按**时间升序补传**，
  **只有确认提交成功才删除队列文件**
- `tools/modbus_rtu_sim.py`：零依赖的 RTU 从站模拟器，配 `socat` 虚拟串口做无硬件验证

### 修复
- RTU 收帧长度计算错误

## [v0.5.0] — 2026-09-17

> v0.3 / v0.4 为内部迭代，能力已并入本版本。

### 新增
- **浅色 / 深色双主题**一键切换 + 矢量图标工厂，设置持久化
- **告警通知体系**：系统托盘通知 + 浮动告警 Toast + 声音提示；分级自动消隐、严重告警常驻

- 设备分组与分组树；断线自动重连（指数退避 1s → 30s）

### 变更
- **采集线程化**：每台设备独占一条 `QThread`，`DeviceConnection` 对象 `moveToThread` 到该线程；
  采样数据经队列 + **定时批量事务**写入 SQLite（200 ms / 200 行），避免高频小事务拖慢界面
